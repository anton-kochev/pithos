# Host-private state provisioning — behavior list

This incremental host-only operation is separate from Docker discovery and from CLI authorization. It never provisions or alters Docker volumes or existing incompatible homes.

1. Given an absolute canonical, owned HOME with trusted ancestors, create the broker root, empty Docker config, stage root, stable manifest root and lease root in a fixed layout with mode 0700; directories must live outside the project and must not be selected from agent-editable configuration. Existing private directories must be regular directories (not symlinks) and have exact mode 0700 (including no sticky/setgid/setuid bits), owned by the effective non-root user; incompatible entries fail before creating new state and without changing them.
2. Generate a fresh unpredictable run ID and exclusive private run directory for each attempt, plus an exclusive manifest directory at `$HOME/.pithos-broker/manifest/<run_id>`. Never silently reuse an existing run directory; a run collision is retried with a new ID. Once a run directory is named, manifest creation failure (including collision) fails without selecting another run ID or removing evidence. Each run's ResourceManifest must open independently; retain run and manifest evidence on failure or crash, including after child cleanup failure.
3. Durably sync newly created directories and their parents before exposing paths; sync the run directory and its parent before attempting manifest creation so failed manifest creation retains durable run evidence. Report errors without logging HOME, credentials or user input. Do not create a Docker config if a malicious or incompatible tree already occupies the path; never populate it with Docker credentials.
4. The lease root must equal `$HOME/.pithos-home-leases`, as required by `HostInputs::validate`, and the broker state must not lie under the workspace. Provisioning does not obtain an exclusive lease or assert that an existing home volume is compatible.
5. Valid host paths may be handed to `HostInputs`; the coordinator independently revalidates. No broker CLI gate removal or real Docker acceptance is implied.
