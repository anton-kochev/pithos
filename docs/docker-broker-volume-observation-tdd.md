# Managed Docker named-volume observation — behavior list

Read-only typed observation for later host-owned database registry integration. This slice does **not** create, adopt, mount or delete Docker volumes, or activate the broker.

1. Observe a validated exact physical name using only the frozen `ManagedDocker` executable/socket/config and its supervised queries; daemon ID must be established and unchanged. A complete bounded list absence returns `Absent { name: VolumeName, daemon_id: String }` for the **queried** physical name and frozen daemon, even if unrelated names appear in the list. This is read-only evidence, *not authorization to create*; missing, truncated, malformed or changed output is not absence evidence. `Debug` stays static/redacted (`Absent`), without exposing either value.
2. For a present volume inspect strict metadata twice; require local driver/scope, no driver options, nonempty bounded creation timestamp, bounded literal labels, and exact name. Return a typed immutable observation with daemon ID, labels and timestamp. Reject foreign/malformed/changed daemon/inspect, missing metadata, or any ambiguous child state. The future registry will require exact broker labels and recorded fingerprint before use.
3. No inferred data continuity from a name; the registry's intent/confirmation and daemon-consumer checks are separate. Native Linux and Docker Desktop acceptance remains outstanding.
