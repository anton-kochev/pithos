# Typed managed-app launch plan — offline policy contract

This slice is intentionally **non-executable**: it validates a frozen, bounded application invocation but does not run Docker or own containers. An eventual executable app owner must first record durable intent, supervise Docker children, inspect exact immutable metadata and reconcile cleanup.

- A logical app handle is bounded, unique per run and distinct from broker infrastructure aliases. The run ID must be exactly the host-provisioned shape: 32 lowercase ASCII hex bytes; logical names remain at most 32 bytes. The frozen name is `pithos-app-` plus 32 lowercase hex characters (first 128 bits of SHA-256 of each component's big-endian u64 byte length followed by its bytes, run then logical); it stays under 63 bytes without embedding either raw identity in the name. Labels retain the original run and logical identity. Only a host-issued immutable image identity, not an agent Docker image/tag/ID or raw argv, may satisfy the launch plan. Do not treat `ImmutableImageId` alone as build provenance.
- Input command is an argv list of bounded literal values; no shell, NUL/control characters, arbitrary Docker flags, interactive input, privileged mode, host bind mounts, published host ports or daemon/socket mounts. Diagnostics and `Debug` redact input.
- The planned Docker argv has exact broker-owned container name and immutable image ID, broker labels, no pull/auto-remove/volume flags, bounded broker network and generated alias (if a trusted network is supplied), fixed security defaults and an unambiguous `--` image/command boundary. It is not public or executed. **The argv alone cannot prohibit anonymous volumes**: an image declaring `VOLUME` causes Docker to create them. Before any future execution, the host owner must separately preflight the exact image's configuration and reject volume declarations (and verify other image entrypoint/configuration assumptions).
- Policy tests record behavioral Red before implementation. The CLI and status protocol remain gated; fake Docker observes zero invocations.

## Evidence

Rust package: `Cargo.toml` edition 2024, MSRV 1.85; substantive `src/broker/`, `src/docker/managed.rs`, and existing broker tests. No dependency or gate changes. New `pub(crate)` module is deliberately unused in production until an owned build, network owner and durable runtime exist; its non-test dead-code allowance is scoped to the module. `HostIssuedAppImage::from_owned_build` accepts a typed immutable ID **only within this crate** and is reserved by contract for a future owned-build caller; `ImmutableImageId` alone is not provenance. `TrustedAppNetwork::from_owned_network` is similarly crate-only and reserved for a trusted network owner. Neither token is an admission or execution capability. The renderer returns an argv vector; there is no `Command` or side-effect path. A literal command token such as `--privileged` occurs only **after** the image and cannot become a Docker option; the image's own entrypoint may still interpret command tokens, so image trust/preflight remains a separate obligation.
