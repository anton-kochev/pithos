# Host Docker discovery and private state — test list

The broker is still default-off. This increment implements **read-only host-selected** Docker discovery; it does not connect to the host coordinator, authorize Pi to query Docker, or change the CLI gate. The caller supplies a previously captured `HostDockerSnapshot` (`PATH`, `DOCKER_HOST`, `DOCKER_CONTEXT`, `DOCKER_CONFIG`, `HOME`, and optionally an existing broker-private config directory). `discover()` does not read the process environment.

## Discovery behavior before production

1. Capture host PATH, DOCKER_HOST, DOCKER_CONTEXT, DOCKER_CONFIG and HOME once; no project YAML, Pi argv, `docker context` command, ambient context or daemon read may select an endpoint. An explicit unsupported/remote endpoint or named context fails without falling back.
2. Resolve an absolute host Docker executable from explicit trusted candidates (PATH order); refuse an unsafe first existing candidate rather than silently skipping to another. Reject empty/relative PATH entries, including entries after the selected candidate. Without PATH, try only the platform's fixed standard executable locations. Validate using `ManagedDocker::new` without spawning. Return canonical paths, **not** a managed owner: future coordinator integration must construct its own owner from the selection and revalidate before use. No `Command::new("docker")` in discovery.
3. Docker endpoint must be an existing local Unix socket. Explicit `DOCKER_HOST=unix:///absolute/path` is accepted only after the frozen adapter validates socket/parents. Without it, Linux tries `/var/run/docker.sock`, macOS Docker Desktop additionally allows the fixed `$HOME/.docker/run/docker.sock`. Never use TCP, SSH, rootless/remote contexts, wildcard binding or Docker socket inside a container.
4. Explicit Docker config must be an existing private static-auth-only directory supported by `ManagedDocker`; an invalid `DOCKER_CONFIG` fails without fallback. Without an explicit config, the caller must supply an existing owner-private **empty** broker config (mode 0700); discovery does not provision it, copy from `.docker`, or mount it into Pi.
5. Every error is static and redacted; discovery does not create directories, launch commands or mutate Docker. Stage/run/lease provisioning is a *separate* host-only operation with its own test list and evidence.

## Ancestor-trust regression (review follow-up)

Discovery delegates admission to `ManagedDocker::new`. Its frozen leaf checks previously accepted an otherwise valid executable beneath a group-writable parent (and similarly exposed socket/config paths to parent replacement). Both the supplied path and its canonical target now require root- or effective-UID-owned ancestors with no group/other write permission. Root-owned sticky writable directories such as `/tmp` remain allowed; owned symlink ancestors (including the macOS `/var` alias) are allowed only when their supplied and resolved chains are trusted. The adapter freezes ancestor identity/permissions and rechecks them before and after each command; a change permanently invalidates the handle without launching another child. This is metadata-based protection, not an fd-based guarantee against races or hostile same-UID/root actors.

Red: `CARGO_HOME=/tmp/pithos-cargo cargo test --offline --test docker_selection group_writable -- --nocapture` failed both new selection assertions: discovery returned `Ok` for a group-writable executable parent and socket parent. `CARGO_HOME=/tmp/pithos-cargo cargo test --offline --test managed_docker test_ancestor_becoming_writable -- --nocapture` returned `Ok(())` instead of `Changed`. Logs: `/tmp/pithos-ancestor-tdd/red.log`, `/tmp/pithos-ancestor-tdd/red-managed.log`. The default Cargo cache lacks `ctrlc`; the existing offline `/tmp/pithos-cargo` cache was used. Green: see `/tmp/pithos-ancestor-tdd/green-final.log` (8 selection and 27 managed-adapter tests passed, including canonical-target and same-target parent-symlink replacement checks). Check/fmt/Clippy logs are in the same directory.

## Evidence

The compile-friendly deny-all implementation produced two behavioral assertion failures in `tests/docker_selection.rs` (`01-red/docker_selection.log`). After the read-only implementation, all six focused tests pass (`02-green/docker_selection.log`); `cargo check --offline`, `cargo clippy --offline --test docker_selection -- -D warnings`, `cargo fmt --all -- --check`, and the 23 existing managed-adapter tests also pass (`02-green/check.log`, `02-green/clippy.log`, `02-green/fmt.log`, `02-green/managed_docker.log`). Logs are under `/tmp/pithos-runtime-tdd/host-discovery/`. The initial attempt with the default `CARGO_HOME=/opt/cargo` was blocked by a registry-cache permission error; tests were run offline with the existing writable `/tmp/pithos-cargo` cache. Tests use a bound local Unix socket, executable scripts that leave a marker if called, and existing private config fixtures; no Docker CLI or daemon is required. Filesystem paths returned by discovery are observations, not capabilities or stable leases; the coordinator has not been connected.
