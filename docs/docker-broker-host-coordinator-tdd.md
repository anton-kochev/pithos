# Offline host coordinator slice (gate remains closed)

## Behavior list

- Host owns raw `.pithos` bytes and explicit absolute Docker executable, Unix socket, private Docker config, canonical project workspace, staging/run/manifest directories and run ID. The only launch command is `dockerfile::PI_LAUNCH_ARGV`; the retained `HostInputs.command` field must be empty. No PATH, Docker environment/context, HTTP or project-selected host paths. The sole HOME use is validating a canonical, trusted, owned host HOME and requiring the existing private lease root at the literal `HOME/.pithos-home-leases` path, matching the legacy caller. Root/foreign identities, workspace aliases, alternate lease roots and missing/unsafe private roots fail before work; no root provisioning or chmod. The lease itself owns only its per-volume entries.
- Parse the raw bytes with `config::load`; require volume-backed sessions, disabled browser and no configured Pi extensions. Project name follows `project::name_from_path`; the legacy volume is `pithos-home-<project>` (as in `sessions::migrate` and `docker::run_request`). Refuse unsupported settings rather than silently changing their meaning.
- Reject a grant without both status and run authority **before** signal installation, Docker queries/builds, credential or lease work; return an ownerless static `HostError::Grant`. Validate run IDs as 1–64 ASCII bytes, first alphanumeric and remaining alphanumeric/`_`/`-`, before any launch work. Install `SignalGuard` on a fresh process with one shared `Shutdown` **before** creating/querying `ManagedDocker` for an authorized run. Use that adapter's `ensure_identity_image` with canonical workspace and private stage. Production uses the platform endpoint constructor (Linux inspected gateway; macOS Docker Desktop); the separate `start_offline` API accepts only a caller-bound offline loopback endpoint and does **not** assert container reachability.
- Transfer the same Docker owner to `BrokerRuntime::begin_with_docker` and then `admit_and_start_pi`. A successful start is not settlement. Poll status/Pi/cleanup via `HostCoordinator`; publish a Pi exit code only after `RuntimePhase::Complete`. Keep signal ownership until completion.
- Failed image/query/endpoint construction returns the actual `ManagedDocker` and `SignalGuard`; runtime construction returns either its prelease Docker owner or its postlease recovery owner with the signal guard. Failed admission returns its actual runtime recovery owner. `HostFailure::poll_cleanup` requests cancellation of retained prelease work or retries runtime cleanup; `RecoveryRequired` is not completion. Neither owner performs cleanup on Drop. Callers must keep polling, not discard unresolved children or durable debt.
